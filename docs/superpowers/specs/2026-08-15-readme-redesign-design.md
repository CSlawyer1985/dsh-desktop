# DSH Desktop README 改版设计

## 目标

把现有 README 从信息齐全但偏平铺的开发说明，升级为兼顾普通下载用户、开源社区访问者与开发者的产品型项目主页。新版应延续作者其他仓库常用的居中标题、少量徽章、快捷导航和清晰章节结构，同时避免徽章堆砌、过量 emoji 与模板化宣传语。

## 受众与阅读顺序

README 首先服务第一次进入仓库、希望快速判断产品用途并下载安装的普通用户，其次服务希望了解实现方式或参与开发的技术用户。

信息顺序为：

1. 这是什么，以及为什么值得使用
2. 官网与最新版下载入口
3. 产品真实界面与关键能力
4. 不同平台如何安装和首次打开
5. 内置 DSH CLI 的工作方式与数据位置
6. 源码构建、签名、部署和排障
7. 作者、开源声明与致谢

## 视觉结构

### 顶部展示区

- 使用居中的项目图标、项目名和一句中文定位。
- 保留 4 至 5 个有实际信息价值的徽章：版本、支持平台、Electron、许可证和 Release 状态。
- 提供“访问官网”“下载最新版”“查看使用说明”三个快捷入口。
- 不使用大面积营销口号或无意义徽章墙。

### 网页截图

在 `docs/images/` 保存两张真实官网截图：

1. `dsh-desktop-home.png`：桌面宽屏下的首页主视觉，展示项目定位和主要下载入口。
2. `dsh-desktop-download.png`：下载区与 macOS 首次打开说明，直接回应未签名安装包被系统拦截的问题。

截图使用当前正式站点内容，统一桌面宽度和清晰度；截图后进行人工检查，避免动画未完成、文字模糊、弹层遮挡或截断。

## 内容设计

### 产品介绍

用一段短文说明 DeepSeek Harness Desktop 是对官方 DSH Web 的非官方桌面封装。突出以下事实：

- 安装后双击即可运行，不要求用户安装 Node.js、npm 或 dsh CLI。
- 官方 `@deepseek-ai/dsh` 及运行组件已经内置。
- 支持 macOS、Windows 和 Linux。
- 继续使用用户本机的 `~/.dsh` 数据与配置。

### 核心能力

使用紧凑的两列表格或短列表，介绍一键启动、运行组件内置、服务复用、生命周期管理、原生窗口体验、异常恢复和数据兼容。文案以具体行为为主，不重复相同卖点。

### 下载与首次打开

- 使用按平台划分的下载表格，并链接到最新版 Release。
- 明确 macOS Apple Silicon / Intel、Windows 安装版 / 便携版、Linux AppImage 的区别。
- 在用户可见位置说明安装包暂未签名以及安全拦截的原因。
- README 只提供足以完成首次启动的步骤；代码签名配置仍放在 `docs/SIGNING.md`，不把内部发布指南混入面向用户的主流程。
- 引导用户访问官网查看图文安装说明。

### 技术与开发信息

保留工作原理、源码构建、环境变量、日志排障、网站部署和图标来源，但放在用户内容之后并适当压缩。使用清晰的路径和命令示例，不引入尚未实现的功能。

## 作者介绍

采用“律师 × AI Builder 并重”的表达：

- 作者名称使用“陈石（CSlawyer）”。
- 身份描述为执业律师、AI Builder 与法律科技实践者。
- 简要说明其关注方向：把法律实务中的风险分级、验证纪律和结构化方法沉淀为可复用的 Agent Skill 与开源工具。
- 链接个人网站、GitHub 和“四明山法师夜校”。
- 保持克制，不虚构履历、机构、奖项或未经确认的头衔。

## 边界

- 不修改应用代码、构建配置或官网正文。
- 不改变 Release 文件和现有下载链接。
- 不把 `HANDOFF.md` 或 `README 2.md` 纳入版本控制。
- 不在本次改版中解决代码签名本身，只清楚说明首次打开方式并链接签名文档。

## 验证

- 两张截图均由正式官网真实渲染，并完成视觉检查。
- README 中所有相对图片和文档链接存在。
- 官网、GitHub Release、作者主页等外链可访问或格式正确。
- 版本号、内置 DSH 版本、支持平台和安装包类型与仓库当前配置一致。
- 通过 `git diff --check`，确认没有 Markdown 空白错误。
