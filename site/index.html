三个核心设计

把"启动服务"这件事，
从终端里拿掉

桌面端只做一件事：让 DeepSeek Harness 像普通 App 一样，双击即用。

自动拉起服务

启动时探测本地端口：已有 dsh web 在跑就直接复用；没有则用安装包内置的运行组件自动拉起，就绪后加载 UI，无需任何命令。

独立桌面窗口

无地址栏、无标签页的原生窗口，固定到 Dock 或任务栏后与普通 App 无异；服务意外退出会弹窗提示，一键重启。

完整复用配置

直接使用本机 ~/.dsh 下的 profile、插件与会话数据，与命令行体验完全一致；退出时自动关闭自己拉起的服务，不误伤其他实例。

每一次启动都有迹可循

工作原理

状态全程可见：日志写入应用数据目录，服务守护进程意外退出时弹窗提示，任何环节出问题都能快速定位。

探测端口

检查 127.0.0.1:3080 是否已有 DSH 服务（按 __DSH_BOOT__ 标记识别）。

启动内置服务

直接加载安装包内置的 @deepseek-ai/dsh，不依赖系统 Node.js，也不会在首次启动时联网下载运行组件。

拉起并等待就绪

用应用自带运行时启动 dsh --profile web，轮询直到服务就绪（最长 120 秒）。

守护与清理

加载 UI；退出应用时自动关闭自己拉起的服务进程，复用中的外部实例保持不动。

下载后打不开？ 查看 macOS 首次运行方法

当前 macOS 安装包尚未取得 Apple Developer 签名。Gatekeeper 可能将它显示为“已损坏”，这类提示通常是系统无法验证发布者，并不等同于文件在下载时损坏。

  1. 1

    打开下载的 DMG，将 DeepSeek Harness 拖入“应用程序”。如果下载的是 ZIP，解压后也请把 App 移入“应用程序”。

  2. 2

    尝试打开一次。如果系统拦截，进入“系统设置 → 隐私与安全性”，向下找到相关提示并点击“仍要打开”。

  3. 3

    如果仍显示“已损坏”，打开“终端”，复制并执行下面这条命令：

xattr -dr com.apple.quarantine "/Applications/DeepSeek Harness.app"

执行后，再从“应用程序”中打开 DeepSeek Harness。

这条命令只移除 DeepSeek Harness 的下载隔离标记，不会关闭 Mac 的整体安全保护。请仅使用本站或项目 GitHub Releases 提供的安装包。

下载后打不开？ 查看 Linux 首次运行方法

AppImage 下载后需要先取得执行权限。这是 Linux 对下载文件的常规保护，并不需要安装到系统目录。

  1. 1

    打开终端，进入 AppImage 所在目录。

  2. 2

    依次执行下面两条命令，赋予执行权限并启动应用：

chmod +x DeepSeek-Harness-*.AppImage ./DeepSeek-Harness-*.AppImage

只为从本站或项目 GitHub Releases 下载的 AppImage 增加执行权限。

· 安装包已内置所需运行组件，安装后无需 Node.js、npm、npx 或终端准备即可启动。 · 全部历史版本见 GitHub Releases。
